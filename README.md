# TerraForge · 世界生成器

用真实的地球物理过程生成虚构星球。地形不是噪声刷出来的，而是板块漂移、碰撞造山、河流侵蚀、雨影效应一步步算出来的。

**在线体验**：https://aforgomon.win/map/

---

## 现在能做什么

- 生成一颗完整的星球（65 万格，约 5 秒），地形、气候、生态、矿藏全部由物理过程推导
- 实时观看生成过程，星球逐帧演化
- 地图树导航：从世界层下钻到大陆层，场景自动从球面切换到平面地图
- 四套视觉风格切换（写实 / 水彩 / 羊皮纸 / 等高线）
- AI 助手：用自然语言查询世界状态、触发生成、切换视图

## 还没做的

- 区域层与地点层的完整渲染（后端能生成，前端只做了大陆层）
- AI 助手的地形编辑能力（当前只有查询和触发生成）
- Tauri 桌面版
- 导出 PNG / JSON

## 技术架构

```
浏览器                         服务器
┌──────────────────┐          ┌──────────────────┐
│ Vue 3 + WebGL2   │  HTTP    │ Rust / axum      │
│ 六角球实例化渲染  │◄────────►│ 作业队列         │
│ 65万格 125fps    │   SSE    │ rayon 并行物理   │
│                  │          │ redb 嵌入式存储  │

```

### 核心 crate

| crate | 职责 |
| --- | --- |
| `tf-core` | 球面几何、确定性随机、噪声、参数 |
| `tf-grid` | 球面六角格（戈德堡多面体）、平面六角格、局部补丁网格 |
| `tf-sim` | 六阶段地球物理流水线 |
| `tf-server` | HTTP API、作业系统、存储 |
| `apps/web` | Vue 3 前端 |

### 物理流水线

1. **板块构造** —— 地幔对流驱动板块漂移，产生地壳厚度场
2. **构造地貌** —— 热沉降、俯冲海沟、碰撞造山、裂谷
3. **侵蚀水文** —— 填洼、流向、汇流、河流下切、坡面扩散
4. **气候** —— 温度带、风场、水汽平流降水、洋流
5. **生态** —— 生物群系、土壤、矿藏
6. **覆盖层** —— 植被、农田

## 本地运行

### 环境要求

- Rust 1.82+
- Node.js 22+ / pnpm
- Windows 需要 MSVC 工具链（Visual Studio Build Tools）

### 启动

```bash
# 后端
cargo run -p tf-server --release

# 前端（另开一个终端）
cd apps/web
pnpm install
pnpm dev
```

打开 http://localhost:5173

### 配置

后端读环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TF_PORT` | 8790 | 监听端口 |
| `TF_DATA_DIR` | ./data | 数据目录 |
| `TF_QUALITY` | standard | 精度档位：economy / standard / high |
| `TF_MAX_CONCURRENT_JOBS` | 1 | 并发生成数 |
| `TF_STATIC_DIR` | 无 | 前端产物目录 |

前端构建时用 `vite build`，base 路径在 `vite.config.ts` 里配置。

## 关键设计

### 为什么用六角格

球面上铺六边形必然有 12 个五边形（欧拉公式决定），但换来的是格子面积一致、邻居等距、可以直接做战棋逻辑。格数 = 10f² + 2。

### 为什么地形不用噪声

噪声能做出"像山的东西"，但回答不了"这座山为什么在这里"。物理模拟的代价是慢，收益是每一块地形都有成因。

### 密钥安全

用户的 API key 只存在浏览器 localStorage，请求从浏览器直连 LLM 提供商。后端全程不接触密钥，也没有任何转发接口。

### 降尺度继承

子图不是独立生成，而是从父图采样边界条件，用软约束拉拢：

```
h_new = h_physics + λ·(h_parent − h_physics)
```

λ 在补丁边缘为 1.0（完全服从父图），中心衰减到 0.3（允许自由生长）。保证放大后海岸线不跑位。
