# 内陆假湖与沉积修正

用户反馈：大陆内部不再整块抬升，但遍布坑湖，形成“超级沼泽”。本次修正针对真实水文和地形，不通过隐藏水面或平滑整块大陆处理。

## 已核实的原因

- 原 Priority-Flood 算出的填洼深度表示“灌满到溢出口需要多深”，被直接写入实际湖深。没有降雨、入流和蒸发限制。
- 侵蚀跳过所有填洼格；`k_deposition` 从未参与计算，坑既不被下切，也不被上游泥沙回填。
- 每个有水格都强制归为湿地，未区分浅水湿地和深湖。
- 渲染将干岸水深设为零，插值会把大半个邻接三角形也染蓝，扩大零碎湖泊的观感。

## 实现

1. `lakes.rs` 建立洼地层级：相邻湖盆先各自蓄水，在真实鞍部交换溢流，填满子盆地后才出现共同水面。每年降雨扣除陆地蒸散后形成径流，汇入湖盆，再按湖面附加蒸发求稳态水位。零降水不产生新水。
2. 路由使用实际地表／水面；干燥封闭盆地可成为汇点。保持上游汇水面积的原单位平方米，水量收支另存，不混作河流流量。
3. 河流下切产生有限泥沙体积，沿汇水关系进入洼地；沉积确实抬高湖床，只在容量用尽后向外输送。记录侵蚀、回填、输出和未落定体积。浮点舍入余量留在未落定账中，不转移到不相关格子。默认沉降率为每年0.3，千年步长下接近完全沉降；这不是泥沙旅行时间模型。
4. 最终气候完成后重算水面；子图在水文前先计算蒸发，旧工程重建自动分区时也读取保存的蒸发数据。
5. 新增内陆水体类别。0.1～2.5米且年均温高于零的水域为简化浅水湿地；深湖或寒冷湖面为内陆水体，不生成陆地土壤。岸线上传有正负的“水面减地面高度”用于裁切，原始物理场不受渲染修改。
6. 工程元数据标记 `depression-hierarchy-annual-balance-v1`，并保存水量和泥沙账。旧工程保留原始场，显示重新生成提示；新规则不会自动改写已保存地形。

## 科学依据与边界

洼地层级和溢流顺序参考 [Depression Hierarchies](https://esurf.copernicus.org/articles/8/431/2020/esurf-8-431-2020.html) 与 [Fill–Spill–Merge](https://esurf.copernicus.org/articles/9/105/2021/)。这是本项目的网格实现，不宣称复制该论文完整算法。

年度陆地蒸散采用 [Turc–Mezentsev/Pike 形式](https://hess.copernicus.org/articles/24/1927/2020/hess-24-1927-2020.html)，湖泊遵循降雨、集水、蒸发和溢流的收支关系，见 [USGS 湖盆水文说明](https://www.usgs.gov/centers/dakota-water-science-center/science/hydrology-devils-lake-basin)。2.5米浅水边界参考 [USFWS 2013 分类](https://www.fws.gov/sites/default/files/documents/Classification-of-Wetlands-and-Deepwater-Habitats-of-the-United-States-2013.pdf)，但本项目没有完整的水生植被和地下水模型，不能视为严格湿地调查分类。

模型仍是年度稳态近似：不求地下水、季节蓄水和历史盐度；湖岸采用格内连续面积近似。泥沙账只覆盖河流下切，坡面扩散和冰川近似不纳入该账。全陆无边界球面沿用全局最低点作为终端的旧约定，不代表完整封闭行星水圈。没有设定全球湖泊数量或面积上限。

## 验证记录

- 新增干盆地、湿湖、湿润上游补给干旱湖、嵌套溢流、泥沙容量与体积守恒、深层洼地、32组地形与气候、双海洋出口以及浅水／深水生态测试。
- DSH 只读审计后，主代理独立核对。其“最高分水岭会生成无限水面”的具体11格反例未复现：海洋连通分量在并查集中保持域外状态；已增加该反例测试。采纳了深链测试补充非零降雨与沉积舍入余量不跨盆地转移的建议。
- 初次完整92项模拟测试中88项通过，4项自动分区测试因旧夹具未分配蒸发数组失败；修正夹具与实际旧工程读取路径后，最终91项通过。两项耗时较长、代码未修改的世界种子及大气细化测试已在前一次完整运行通过，最终定向运行未重复。
- 服务端20项、前端42项、类型检查和生产构建通过。完整生成、图像及发布结果随后记录。

受控重放使用此前保存的655362格球面工程：原来7410个湖格、1456个湖泊连通域、693个单格湖；仅修水量仍有6344个湖格。接入18次额外侵蚀／回填后为1282格、143个连通域、44个单格湖。此对照是在旧地形上额外演化，不能冒充从种子重新生成的前后对照；独立结果见后续验收。

本地后台测试服务启动被自动审批拒绝，只返回“blocked by policy”。改用 `offline_world_qa` 在单进程中调用正式路由、生成、保存和诊断，不监听端口；GPU检查支持直接读取这些产物。浏览器／手机交互验收缺口仍以根目录 `design-qa.md` 为准。
